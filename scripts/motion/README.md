# 动效测量台

`scripts/motion/` 用来量转场动画：在 `dist`（先 `npx vite build`）加演示数据（`?demo=1`）上开一个无头 Chrome，逐帧采样，出数字表、慢放条带和 Chrome trace。动效规则本身见 [ui-guidelines](../../docs/development/ui-guidelines.zh-CN.md)「动效」一节，性能预算见 [motion-performance-notes](../../docs/development/motion-performance-notes.md)。

依赖：Python 3 + Playwright（`pip install playwright`，浏览器装到 `PLAYWRIGHT_BROWSERS_PATH` 或用系统 Chrome）+ Pillow。

## 脚本

| 脚本 | 用途 |
|---|---|
| `harness.py` | 公共部分：开应用、点击、逐帧采样、算指标。其他脚本都从这里导入 |
| `bench.py [--only <场景前缀>] [--throttle 4] [--json <out>]` | 跑写信信封、概览卡 ↔ 详情页、设置卡叠三类转场，输出数字表 |
| `strip.py` | 慢放条带：动画放慢 5 倍，按真实时间点截图拼成一张，给人看编排 |
| `trace_click.py <路由> <选择器> <out.json> [close]` | 点开（或关掉）一个由按钮触发的弹层 / 形变时抓 Chrome trace |
| `trace_swaps.py <trace>...` | 首次输入后的 DrawAndSwap 帧间隔，以及 GPU / 光栅长任务（> 8 ms） |
| `trace_frames.py <trace>` | 主线程每帧（BeginMainFrame > 4 ms）与分层 / 绘制耗时 |
| `trace_nest.py <trace> <起始ms> <窗口ms>` | 展开窗口内主线程 ≥ 1 ms 的任务，附样式 / 布局失效提示 |
| `video_grab.sh <视频> <输出目录> <起> <止> <步长> [宽]` | 录屏逐帧抽图：一次只解一帧、CPU 软解、2 线程 |
| `contact_sheet.py <目录> <输出> <列数> [宽] [起 止]` | 把抽出的帧拼成带文件名的联系表 |

环境变量 `ZB_MOTION_GPU=1` 让无头 Chrome 走真显卡（Windows 上是 D3D11）。默认的软件 GL 量不出高分屏上 GPU 光栅化造成的那一下卡顿；量弹窗、形变这类「窗口长大时正文光栅化」的问题时要打开。

## 怎么测

- 默认 **CPU 降速 4×、DPR 2**、1440×900，贴近高分屏上的 WebView2。不降速在开发机上几乎量不出卡顿。页面形变另跑一遍 1×（`--throttle 1`），原因见下。
- 测量时挡掉自动降级（`html[data-effects=lite]`）：降速以后机器分级会判成低档、整套动效被关，量到的就是另一套东西。
- 采样是页面里的 `requestAnimationFrame`：每帧读一遍计算样式（透明度连乘到根、`clip-path` 裁出来的可视框）。**主线程被堵住的那段它看不见**：合成器上的动画照走，采样却一帧都没有。所以 4× 下页面形变的去程 / 回程会被挂载新页的长任务淹没，掉头的比值以 1× 为准。
- 截慢放条带时放慢的是动画本身（CDP `Animation.setPlaybackRate`），不降速：DPR 2 截图本身就慢，不放慢动画的话帧时间全错。
- 指标：
  - 起步：点击到第一帧可见变化。
  - 最长停顿帧：变化段里相邻两帧完全一样的最长连续数。
  - 空板帧：窗口已经比卡大 1.5 倍，里面的卡拷贝和内容都淡于 0.2。
  - 截断：收起途中还很大的板，下一帧就没了。
  - 被吞的点击：连点时点了却没换路由。
  - 回程 / 去程：窗口开始长 → 开始缩 → 落回卡上（或撤掉）两段的时长比。
- 「起步」只看第一处变化，看不出窗口长大时里面有没有东西。判断编排要配合 `strip.py` 的条带一起看。

## 基线（2026-11-12 / 11-13）

数字因机器而异，这里只记结论，用来对比改动前后。

**写信（弹窗 + 信封，4×）**：信封第一帧就在笔 / 「动笔写信」按钮那里，从按钮的大小长出来（第一帧离起点 0 px）；关的时候沿原路飞回，和遮罩同一刻散掉（收尾差约一帧）。

**设置卡叠（4×）**：开合全部 0 截断、0 空板帧，最长停顿 1–3 帧；连点 5 次开关一次都不吞。开到一半按 Esc 是同一组动画掉头（最长停顿 1 帧）。卡包往下滚过再点开时，页头和总览一起从刚才看到的位置走过去。

**概览卡 ↔ 详情页**：

- 1× 下开到一半按返回，回程 / 去程在 0.76–1.2 之间，0 空板帧、最长停顿 1 帧；快速连点五次开 / 返回，结束时文档里只有一页、没有残留的形变层。
- 展开时窗口先停在卡上：新页轻着挂（图表只放壳），图表一帧一张地挂在卡拷贝后面，挂完（上限 260 ms）、帧稳（上限 120 ms）才起飞。1×（DPR 2，心率页 5 张图）点击到起飞约 370–480 ms；睡眠页（没有图表）约 290 ms。起飞后窗口里每一帧都是带图表的真页面，落地后没有重画。无头 Chrome 的帧间隔 8 / 17 ms 交替，永远判不成「稳」，所以总会等到帧稳的上限；真机上是两三帧。
- 4× 下起飞会被新页自己的长任务拖到 1 秒以上。那种机器本来就走低特效。

**弹窗 / 信纸打开（`ZB_MOTION_GPU=1`、1920×1080、DPR 2、1×）**：

| 场景 | 最长帧 | 主要原因 |
|---|---|---|
| /journal「记一条伤病」「登记比赛」「记一件事」 | 130–160 ms，之后 30–60 ms 抖几帧 | 窗口刚开始长时，正文整块 GPU 光栅化（RendererRasterWorker 约 100 ms） |
| 同上，正文 `visibility: hidden`（对照） | 29–40 ms | 确认是正文 |
| 同上，去掉遮罩背景模糊 / 面板玻璃 / 阴影 | 125–147 ms | 不是它们 |
| 设置「动笔写信」，空闲预排信纸文字（`paperWarm.ts`） | 约 147 ms，主线程最长任务 142 → 12 ms | 剩下的是光栅 |

试过没用的：开的时候停在起点等帧稳再放、让正文先以低透明度画一次、正文加 `will-change: transform`。光栅化是跟着裁切窗口长大才发生的。

## 已知没解决的

- 4× 下新页挂载本身仍有一段长任务：展开第一下的反馈是「卡拷贝顶在原位」，要等长任务过去窗口才开始长。要再快只能让新页挂得更轻，或者拆成多帧挂。
- 收回途中再按 Esc，会把剩下的部分在 200 ms 内放完（落到卡上），而不是掉头：收回本来就是「返回」，再按一次 Esc 的意思是「快点」。打开途中按 Esc 或返回才是掉头。
- 4× 下概览 → /sleep → 返回，返回后约 1 s 处有两段 0.7–1.0 s 的长任务（样式、布局、光栅和 `getBoundingClientRect`），是降速下的老问题。
