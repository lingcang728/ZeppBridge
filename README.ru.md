> [!IMPORTANT]
> ZeppBridge — независимый неофициальный проект с открытым исходным кодом. Он не связан с Zepp Health, Huami или Amazfit и не имеет их поддержки. Используйте его только с аккаунтами и данными, к которым у вас есть законный доступ.

> Приложение следует языку системы при первом запуске, а в Настройках есть переключатель языка. Эта страница поддерживается вровень с [английской версией](README.md), и ничего здесь не описано щедрее, чем реализовано на деле.

## Разве этого нет в приложении Zepp?

Есть — но только на вашем телефоне, только так, как решает показать официальное приложение, и живёт оно на чужом сервере. ZeppBridge закрывает несколько конкретных вещей:

- **Смотреть на нормальном экране.** Долгосрочные тренды пульса, сна, тренировок, восстановления, стресса и SpO₂ за 7 дней / 1 месяц / 6 месяцев.
- **Данные лежат на вашем компьютере.** Всё складывается в один файл на вашей машине. Работает офлайн, переживает смену телефона, удаление аккаунта и редизайны приложения.
- **Можно дозагрузить историю ещё до установки.** Месяц за месяцем, с паузой и продолжением, и честно: в каких месяцах в облаке действительно ничего не было, а какие просто ещё не скачаны.
- **Бэкапы, которые реально восстанавливаются.** Снимки всей базы с контрольными суммами и проверкой целостности, а перед восстановлением показывается разница в числе записей.
- **Экспорт когда захотите.** JSON, CSV и GPX — кидайте в Excel, Strava или свои скрипты.
- **Передать ИИ в один шаг.** Выберите диапазон дат и типы данных; приложение упакует их в понятный модели вид, уберёт идентифицирующие детали и скопирует в буфер обмена.
- **Можно пользоваться без окна.** В комплекте — неинтерактивный CLI (ставится в Планировщик заданий или cron) и MCP-сервер только на чтение, чтобы модель могла спрашивать ваши локальные данные без их ухода с машины.

Одно стоит сказать прямо: **он не будет приукрашивать ваши данные.**

Не надели часы в тот день — на графике дыра. Часы что-то никогда не мерили — интерфейс пишет «не предоставлено», а не `0`. Нет GPS-трека — нет карты. В данных о здоровье выдуманная гладкая кривая хуже честного разрыва.

То же со словом «полный»: интерфейс заявляет **полную локальную копию** только когда журнал покрытия показывает, что по каждому месячному блоку есть итог. До этого он пишет «локальная копия успешно синхронизированного диапазона».

## Какие устройства поддерживаются

**Если ваше устройство синхронизируется с приложением Zepp — пробуйте.** ZeppBridge читает то, что ваш аккаунт хранит в облаке; с часами он не разговаривает, поэтому к конкретным моделям не привязан.

Встроенный каталог узнаёт 52 продукта Amazfit семейств **GTR, GTS, T-Rex, Balance, Active, Bip, Cheetah, Falcon, Helio и Band** (часы, браслеты, ремешки, кольца). Узнанные устройства показывают правильное имя модели и изображение; неузнанные всё равно синхронизируются — просто с общим именем, а своё вы можете указать вручную.

Какие метрики вы реально получите, зависит от того, что меряют ваши часы. После подключения страница настроек перечислит это для вашего аккаунта, пункт за пунктом.

## Скачивание и установка

Свежая сборка — на странице [Releases](https://github.com/lingcang728/ZeppBridge/releases).

**Windows**

1. Скачайте `ZeppBridge_<версия>_x64-setup.exe` (или `.msi`) и запустите.
2. Сертификата для подписи кода пока нет, поэтому Windows может предупредить о неизвестном издателе. Выберите **Подробнее → Выполнить в любом случае**.
3. Следующие версии ставятся поверх; ваши данные не трогаются.

**macOS (Apple Silicon)**

> **Это неподписанная сборка.** Нет ни сертификата Apple Developer ID, ни
> нотаризации, поэтому macOS откажется открывать приложение, пока вы сами не
> снимете флаг карантина. Шаги ниже — осознанный обход, а не исправление —
> см. [#2](https://github.com/lingcang728/ZeppBridge/issues/2).

1. Скачайте `ZeppBridge_<версия>_aarch64.dmg` и перетащите `ZeppBridge.app` в «Программы».
2. Первый запуск не удастся. Какое сообщение вы увидите, зависит от версии macOS:
   - **«неустановленный разработчик»** → **правый клик по приложению → Открыть → Открыть.**
   - **«ZeppBridge повреждён и не может быть открыт»** → правый клик *не*
     поможет. Выполните в Terminal, затем откройте приложение как обычно:

     ```bash
     xattr -dr com.apple.quarantine /Applications/ZeppBridge.app
     ```

   Приложение на самом деле не повреждено. Так Gatekeeper говорит о любом
   скачанном пакете без нотаризации. Запускайте такую команду только для
   софта, которому вы решили доверять, — каждую строку этого проекта можно
   прочитать на GitHub и собрать самостоятельно.
3. Сборки macOS проходят CI (компиляция, clippy, тесты) и один смоук-тест
   участника на Apple Silicon. У мейнтейнера нет Mac, и он не может
   самостоятельно проверить синхронизацию или работу Связки ключей. Если это
   для вас важно — берите Windows.

Почему пока так: сама нотаризация Mac не требует — CI уже работает на
раннерах macOS и могла бы подписывать и нотаризовать там. Не хватает только
подписки Apple Developer Program (99 USD/год), которую проект не покупал.
Если это изменится, раздел исчезнет.

**Linux (x86_64)**

> **Собирается, но запускать пока некому.** CI компилирует, гоняет тесты и
> собирает пакеты на каждый push. Чего *не* было — полного цикла
> «вход → синхронизация» на настоящем Linux-десктопе, включая то, правильно
> ли токен ложится в ваше хранилище ключей. Считайте это сборкой, которую вы
> помогаете тестировать, а не релизом.

На странице релизов публикуются Flatpak, `.deb`, `.rpm` и AppImage.
Ничего не подписано; сверяйте загрузки с `SHA256SUMS.txt`.

```bash
sudo apt install ./ZeppBridge_<версия>_amd64.deb      # Debian, Ubuntu
sudo dnf install ./ZeppBridge_<версия>_x86_64.rpm     # Fedora, RHEL
flatpak install ./ZeppBridge_<версия>_x86_64.flatpak  # любой дистрибутив
```

В [руководстве по Linux](docs/guides/linux.md) написано, куда складываются
данные, как хранится токен без системного хранилища ключей и как собрать из
исходников.

Есть ещё [headless-образ контейнера](docs/guides/docker.md) только с CLI и
MCP-сервером — держать библиотеку синхронизированной на NAS или сервере.
Войти в аккаунт он не умеет — это всё равно нужно один раз сделать в
настольном приложении.

**Не поддерживается**: Intel Mac, мобильные.

### Что проверено на какой платформе

Одно приложение, один интерфейс, те же функции на всех трёх — разница лишь в
том, сколько из этого кто-то реально проверил. Спросить здесь лучше, чем
гадать.

| | Windows 10/11 (x64) | macOS Apple Silicon | Linux x86_64 |
| --- | --- | --- | --- |
| Интерфейс и функции | одинаковые | одинаковые | одинаковые |
| Собирается в CI | да | да | да |
| Автотесты в CI | да | да | да |
| Установщик открывается без обходов | да (предупреждение о неизвестном издателе) | **нет** — см. заметку о неподписанной сборке выше | да |
| Вход, синхронизация, экспорт | проверено мейнтейнером на каждом релизе | только смоук-тест участника | **ещё никто** |
| Хранилище учётных данных | Диспетчер учётных данных, проверено | Связка ключей, независимо не проверено | Secret Service, **ещё никто** |
| Автообновление | проверено | собрано, независимо не проверено | н/д — ваш пакетный менеджер |

Мейнтейнер разрабатывает на Windows, Mac у него нет и Linux-десктопом он не
пользуется. Ничто выше не утверждает, что macOS или Linux сломаны — это
фиксация того, кто что проверял. Если вы на одной из этих платформ и что-то
ведёт себя не так, репорт действительно полезен.

**С версии 1.0.0 схема локальной базы и путь обновления считаются тем, что поддерживают долгосрочно**: перед каждой миграцией автоматически делается бэкап, а снимки можно проверять и восстанавливать. Данные остаются локальными — но снимки живут на том же диске, что и база, поэтому **если боитесь отказа диска, скопируйте один куда-нибудь ещё сами.**

## Первое подключение

1. Откройте ZeppBridge и зайдите в **Настройки** в боковой панели.
2. Нажмите подключиться. Откроется **официальная страница входа Zepp** в отдельном окне; войдите со своими обычными учётными данными.
3. Когда появится «подключено», окно закроется, и приложение запустит первую синхронизацию. Дайте ему секунд 40.

Работают и аккаунты материкового Китая, и международные; приложение само определит, к какому региональному серверу вы относитесь.

Первая синхронизация тянет 30 дней, чтобы на экране быстро что-то было, а потом продолжает в фоне, пока не наберётся 180 дней. Прогресс виден, остановить можно в любой момент. Дальнейшие синхронизации — инкрементальные.

Каждый селектор «последние N дней» в приложении — на экранах тренировок и тела и на странице экспорта — читает вашу **локальную** библиотеку, а не облако. Выберете диапазон глубже того, что есть на машине, — приложение скажет об этом и предложит дозагрузить остальное. Пустой участок на графике значит *ещё не скачано*, а не *вы тогда ничего не записывали*.

Для истории старше 180 дней откройте **Долгосрочный архив и полная история** в Настройках: выберите 1/2/3 года или произвольное начало, и дозагрузка пойдёт по месяцам. Остановиться можно в любой точке и продолжить позже. Перед стартом оценивается объём на диске — по реальной скорости накопления именно ваших данных, а не по зашитой константе.

Если диапазон шире вашего локального срока хранения, приложение потребует сначала включить долгосрочный архив; иначе только что скачанная история будет подчищена после следующей успешной синхронизации.

Застряли на входе? См. [руководство по подключению](docs/guides/connection.md) — там диагностика и два запасных способа.

## Что вы получаете

**Тренды**

| Страница | Что показывает |
| --- | --- |
| **Обзор** | Пульс за последние часы, шаги сегодня, структура вчерашнего сна, эта неделя против ваших же прошлых 28 дней, входы в состояние тела и тренировочный статус. Каждая карточка открывается |
| **Пульс** | Полная кривая за 24 часа плюс дневные тренды пульса в покое и HRV по двум определениям |
| **Дневная активность** | Дневные тренды шагов, дистанции, активных калорий и активных минут |
| **Состояние тела** | Восстановление, стресс, SpO₂, HRV, частота дыхания и пульс в покое во времени |
| **Тренировочный статус** | VO₂max, тренировочная нагрузка, лактатный порог, PAI и завышен или занижен недавний объём |
| **Недавние записи** | Каждый сеанс сна и каждая тренировка, все открываются в деталях |
| **Детали тренировки** | Дистанция, темп, пульс, покилометровые отрезки, GPS-трек; у бега ещё мощность и техника |
| **Устройства** | Откуда взялась модель каждого устройства (совпадение по каталогу или ваше назначение), прошивка, свежие данные — переназначить можно в любой момент |
| **Здоровье данных** (Настройки → Дополнительно и обслуживание) | Состояние получения / разбора / записи каждого потока — означает ли пропуск «не синхронизировано» или «никогда не измерялось» |

Метрика без данных не висит с прочерком «—»; она просто не появляется.
А кривая рвётся там, где больше 15 минут не было ни одного отсчёта, вместо
того чтобы тянуть прямую между двумя концами.

**Инсайт после тренировки и еженедельный отчёт**

После тренировки приложение сравнивает её с вашей же историей: недавние пробежки в той же дистанционной полосе, и как отличаются темп, пульс и тренировочная нагрузка — с указанием, на скольких отсчётах это стоит и какова уверенность. **Базовая линия — вы, а не норма популяции.** Когда отсчётов мало, оно прямо говорит об этом, а не занижает планку ради одной фразы. Это факты и свидетельства; интерпретация остаётся за ИИ.

**Передать ИИ**

Встроено несколько шаблонов промптов (сводка формы, тренировочный инсайт, оценка восстановления, анализ сна). Выберите шаблон и диапазон — приложение упакует данные, уберёт идентификаторы устройств и точные локации, скопирует в буфер обмена и откроет выбранный вами сайт ИИ.

На странице деталей тренировки есть своя кнопка «передать ИИ» с областью
**только эта тренировка**: сама тренировка и поточечные метрики, записанные
пока она шла. Дневные записи вроде сна и шагов в пакет не входят.

Пакеты больше 2 МБ пишутся в файл на рабочем столе — готовый, чтобы
перетащить в диалог.

**Экспорт файлов**

- **JSON** — полные структурированные данные, для скриптов или моделей
- **CSV** — табличная сводка для электронных таблиц
- **GPX** — стандартные треки для Strava, Garmin и других

Что входит в экспорт: сводки тренировок (тип, начало и конец, дистанция,
калории, средний и пиковый пульс, тренировочная нагрузка), дневные метрики
(шаги, пульс в покое, HRV, SpO2, стресс, частота дыхания, PAI, VO2max) и
сеансы сна со шкалой фаз. Выбор **Полный** вместо **Сводка** добавляет
посекундные ряды тренировок и отдельные отсчёты пульса.

`.fit` — отдельный формат экспорта, один файл на тренировку, пишется в
выбранную вами папку. В него идут посекундные ряды, которые ZeppBridge
декодировал из деталей тренировки Zepp: GPS-трек, пульс, скорость, высота,
мощность бега, время касания земли и вертикальная осцилляция, плюс
покилометровые круги и события паузы. Поля, которые никогда не измерялись,
просто отсутствуют — ничего не подбивается, чтобы файл выглядел полным.
Каденс намеренно опущен: его единицы не свести ни с одним сводным полем,
которое у нас есть, а неверная единица молча дала бы вдвое больше.

Чего в экспорте нет: `.tcx`, данных аккаунта, токенов и серийных номеров
устройств. GPS-треки есть в GPX и FIT, и только для тренировок, где трек
реально был.

**Со временем не тяжелеет**

Сырые облачные ответы — самое объёмное в локальной базе. ZeppBridge хранит
их сжатыми: всё свежесинхронизированное приходит уже сжатым, а первый запуск
после обновления в фоне сжимает накопленное и возвращает место на диске —
с прогрессом наверху окна, который исчезает по завершении.

Перед заменой ответ распаковывается обратно и сравнивается побайтово; всё
несовпавшее пропускается: сырой ответ — единственная основа локального
переразбора, поэтому не сжать всегда лучше, чем сжать криво. Замеренная база
на 211 МБ сжалась до 55 МБ.

**Оставьте работать**

Закрытие окна оставляет приложение в трее — оно продолжает синхронизироваться
само. Не хотите, чтобы работало, — правый клик по иконке в трее и выход.

**Без окна**

В каждый релиз также входит `zeppbridge-tools-<версия>-<платформа>.zip` с двумя программами:

- `zeppbridge-cli` — неинтерактивный: `status`, `sync`, `export`. Коды выхода — стабильный контракт, так что он спокойно ставится в Планировщик заданий или cron.
- `zeppbridge-mcp` — MCP-сервер только на чтение по stdio. Ни портов, ни сети. Позволяет модели спрашивать ваши локальные данные без их ухода с машины.

Использование и примеры конфигурации — в [CLI и MCP](docs/reference/cli-and-mcp.md).
Раздел MCP в Настройках также предлагает готовый блок текста, который можно
вставить прямо ИИ, — оно проведёт вас по настройке под вашу машину.

**Локальный REST только на чтение**

В Настройках можно включить эндпоинт только на чтение, привязанный строго к `127.0.0.1`, — для ваших скриптов. По умолчанию выключен, после включения требует токен, не отдаёт никаких учётных данных и никогда не слушает локальную сеть.

## Частые вопросы

**Компьютер должен быть всё время включён?**
Нет. Каждый запуск догоняет пропущенный период.

**Можно бросить приложение Zepp на телефоне?**
Нет. Цепочка такая: часы → приложение Zepp на телефоне → облако Zepp → ZeppBridge. Часам всё ещё нужно телефонное приложение для выгрузки. Открывайте его время от времени.

**За это могут забанить аккаунт?**
ZeppBridge использует ваши же учётные данные и **делает только запросы на чтение** — во всём проекте нет ни одного запроса на запись; можете проверить grep'ом. По поведению это то же самое, что открыть официальное приложение и посмотреть свои данные. Это всё равно неофициальное использование, и гарантий от имени Zepp мы дать не можем.

**Метрика пришла пустой.**
Сначала проверьте, мерили ли её часы вообще. Некоторые метрики (лактатный порог, VO₂max) обновляются только после определённых тренировок — несколько раз в год. Страница настроек показывает каждую по вашему аккаунту — учтите: **«не получено» — не то же самое, что «часы не поддерживают»**: API Zepp возвращает пустой ответ и для несуществующих данных, *и* для имён потоков, которые никогда не были валидными, так что пустота сама по себе ничего не доказывает.

**Где мои данные?**
- **Windows**: папка `data` рядом с каталогом установки (не `%APPDATA%`). В Настройки → Дополнительно есть кнопка, чтобы её открыть.
- **macOS**: `~/Library/Application Support/com.zeppbridge.ZeppBridge/data`
- **Linux**: `~/.local/share/zeppbridge/data` (Flatpak:
  `~/.var/app/com.zeppbridge.app/data/zeppbridge/data`). AppImage и
  распакованный tarball держат `data/` рядом с исполняемым файлом — см.
  [руководство по Linux](docs/guides/linux.md).

**Приложение не стартует — окно так и не появляется.**
Смотрите две вещи, в этом порядке:

1. **Диалог с ошибкой.** Начиная с v2.1.2 сбой запуска показывает диалог с
   точной папкой и ошибкой ОС вместо тихого выхода. Раньше версии выходили
   молча, и это выглядело как «иконка в трее есть, а клик по Открыть ничего не
   делает» — та иконка была огрызком уже умершего процесса.
2. **Лог.** `logs/zeppbridge.log` внутри папки данных (см. предыдущий вопрос),
   плюс `logs/startup-error.log`, если прошлый запуск упал до появления окна.
   Прикладывайте их к баг-репорту; внутри — пути и номера версий, данных
   аккаунта там нет.

Самая частая причина на Windows — папка данных, в которую приложение не может
писать: `.msi` ставится в `Program Files`, куда у обычного пользователя нет
прав записи. С v2.1.2 приложение в этом случае отступает в
`%APPDATA%\zeppbridge\ZeppBridge\data` (если в заблокированной папке уже нет
базы — иначе оно говорит об этом, а не молча стартует с пустой). Можно также
указать любое место переменной окружения `ZEPPBRIDGE_DATA_DIR`.

**После удаления данные остаются?**
Да. Удаление оставляет папку `data`, бэкапы, журнал покрытия и настройки нетронутыми. Хотите убрать — удалите вручную.

**Базу можно бэкапить и восстанавливать?**
Да. В Настройках можно в любой момент сделать снимок всей базы — каждый с SHA-256 и проверкой целостности. Восстановления ставятся в очередь и применяются при следующем запуске — единственный момент, когда файл можно атомарно подменить, — а на шаге очереди сначала показывается разница в числе записей. См. [бэкап и восстановление](docs/guides/backup-and-restore.md).

**У меня несколько часов — данные не смешаются?**
Нет. Каждая запись несёт, с какого устройства она пришла, и интерфейс держит
их раздельно.

**Что-то уходит на ваши серверы?**
Данные здоровья, детали тренировок и учётные данные никогда не покидают вашу машину. Только если вы явно подтвердите «отправить отчёт об ошибке», приложение отправит версии приложения/парсера, ОС, безопасные подсказки о модели и структуру полей для нераспознанных продуктов, версию прошивки, неизвестные коды тренировок с количеством, а также числовой код ошибки последнего запроса, который облако Zepp отклонило (число, какой поток данных и когда — никогда не текст ответа облака). Оно никогда не отправляет аккаунты, токены, серийные номера, ID устройств, GPS, значения здоровья, сырые ответы или локальные пути. Автоматической телеметрии и фоновых отчётов о сбоях нет.

## Приватность

- **Учётные данные** по умолчанию живут в системном хранилище (Диспетчер учётных данных Windows / Связка ключей macOS / Secret Service в Linux). Если связку ключей macOS разблокировать нельзя, можно явно выбрать приватный файл в открытом виде; см. [руководство по хранению учётных данных на macOS](docs/guides/macos-credentials.md). В Linux также поддерживаются файловое хранилище и переменные окружения; см. [руководство по Linux](docs/guides/linux.md). Файловое хранилище защищает слабее системного и никогда не включается просто из-за сбоя последнего.
- **Данные здоровья** — это незашифрованный файл базы на вашем компьютере. Если машина общая, пользуйтесь разными учётными записями ОС.
- **Пакеты для ИИ сначала обезличиваются**: идентификаторы устройств, MAC-адреса и точный GPS вырезаются, а файл перечисляет, что убрано. Точные треки попадают в пакет только по вашему явному согласию.
- **Карты рисуются локально.** Никаких запросов к сторонним картографическим сервисам.
- **Отчёты об ошибках требуют явного подтверждения**, используют фиксированный белый список, собираются локально, не требуют аккаунта GitHub и никогда не публикуются автоматически как issue.
- Синхронизация обращается к серверам Zepp, так что полностью офлайновым это приложение не является.

См. [безопасность и приватность](docs/reference/security-and-privacy.md). О проблемах безопасности сообщайте через приватный канал уязвимостей GitHub, а не публичным issue.
