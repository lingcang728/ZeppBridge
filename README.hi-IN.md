> [!IMPORTANT]
> ZeppBridge एक स्वतंत्र, अनौपचारिक ओपन-सोर्स प्रोजेक्ट है। इसका Zepp Health, Huami या Amazfit से कोई संबंध या समर्थन नहीं है। इसे सिर्फ़ उन्हीं अकाउंट और डेटा के साथ इस्तेमाल करें जिन तक पहुँचने का अधिकार आपके पास है।

> ऐप पहले लॉन्च पर आपकी सिस्टम भाषा का पालन करता है, और सेटिंग्स में भाषा बदलने का स्विच है। यह पेज [अंग्रेज़ी संस्करण](README.md) के साथ-साथ रखा जाता है, और यहाँ कुछ भी लागू होने से ज़्यादा बड़ा बता कर नहीं लिखा गया है।

## यह सब Zepp ऐप में पहले से नहीं है?

है — लेकिन सिर्फ़ आपके फ़ोन पर, सिर्फ़ उसी तरह जैसे ऑफ़िशियल ऐप दिखाना चुनता है, और वह किसी और के सर्वर पर रहता है। ZeppBridge कुछ ख़ास बातें सुलझाता है:

- **असली स्क्रीन पर देखें।** हार्ट रेट, नींद, वर्कआउट, रिकवरी, स्ट्रेस और SpO₂ के लंबे-समय ट्रेंड — 7 दिन / 1 महीना / 6 महीने।
- **डेटा आपके अपने कंप्यूटर पर रहता है।** सब कुछ आपकी मशीन की एक फ़ाइल में उतरता है। ऑफ़लाइन भी चलता है, और फ़ोन बदलने, अकाउंट डिलीट होने या ऐप के रीडिज़ाइन से कोई फ़र्क़ नहीं पड़ता।
- **इंस्टॉल करने से पहले का इतिहास भी भर सकते हैं।** महीने-दर-महीने, रोकने और फिर शुरू करने लायक, और ईमानदारी से बताता है कि किन महीनों में क्लाउड के पास सच में कुछ नहीं था और कौन से बस अभी तक नहीं लाए गए।
- **बैकअप जो सच में रीस्टोर होते हैं।** पूरे डेटाबेस के स्नैपशॉट, चेकसम और इंटीग्रिटी जाँच के साथ, और रीस्टोर से पहले रिकॉर्ड-गिनती का diff दिखता है।
- **जब चाहें एक्सपोर्ट करें।** JSON, CSV और GPX — Excel, Strava या अपनी स्क्रिप्ट में डाल दें।
- **एक क़दम में AI को सौंपें।** तारीख़-सीमा और डेटा टाइप चुनें; ऐप उसे मॉडल-पठनीय रूप में पैक करता है, पहचान बताने वाली जानकारी हटाता है और क्लिपबोर्ड पर कॉपी करता है।
- **बिना विंडो खोले भी काम चलता है।** साथ में एक नॉन-इंटरैक्टिव CLI (Task Scheduler या cron से शेड्यूल कर सकते हैं) और एक सिर्फ़-रीड MCP सर्वर आता है, ताकि कोई मॉडल आपका लोकल डेटा पूछ सके बिना डेटा के मशीन छोड़े।

एक बात साफ़-साफ़ कहनी चाहिए: **यह आपका डेटा सजा-धजा कर नहीं दिखाएगा।**

उस दिन घड़ी नहीं पहनी थी, तो चार्ट में ख़ाली जगह होगी। घड़ी ने कभी कुछ मापा ही नहीं, तो इंटरफ़ेस "नहीं दिया गया" लिखता है — कभी `0` नहीं। GPS ट्रैक नहीं तो मैप नहीं। हेल्थ डेटा में बनाई हुई चिकनी कर्व एक ईमानदार ख़ाली जगह से बदतर है।

यही बात "पूरा" शब्द पर भी लागू है: इंटरफ़ेस तभी **पूरी लोकल कॉपी** कहता है जब कवरेज लेजर दिखाए कि हर मासिक चंक का फ़ैसला हो चुका है। तब तक वह कहता है "सफलतापूर्वक सिंक हुई सीमा की लोकल कॉपी"।

## कौन से डिवाइस सपोर्टेड हैं

**अगर आपका डिवाइस Zepp ऐप से सिंक होता है, तो आज़माने लायक है।** ZeppBridge वह पढ़ता है जो आपका अकाउंट क्लाउड में रखता है; वह घड़ी से बात नहीं करता, इसलिए किसी ख़ास मॉडल से बँधा नहीं है।

बंडल किया हुआ कैटलॉग **GTR, GTS, T-Rex, Balance, Active, Bip, Cheetah, Falcon, Helio और Band** फ़ैमिली के 52 Amazfit प्रोडक्ट पहचानता है (घड़ियाँ, बैंड, स्ट्रैप, रिंग)। पहचाने गए डिवाइस सही मॉडल नाम और प्रोडक्ट तस्वीर दिखाते हैं; न पहचाने गए भी सिंक करते हैं — बस एक जेनरिक नाम दिखता है, और आप अपना डिवाइस हाथ से चिन्हित कर सकते हैं।

आपको असल में कौन से मेट्रिक्स मिलेंगे, यह इस पर निर्भर है कि आपकी घड़ी क्या मापती है। कनेक्ट करने के बाद सेटिंग्स पेज आपके अकाउंट के लिए यह आइटम-दर-आइटम सूची बनाता है।

## डाउनलोड और इंस्टॉल

नई बिल्ड [Releases](https://github.com/lingcang728/ZeppBridge/releases) से लें।

**Windows**

1. `ZeppBridge_<वर्ज़न>_x64-setup.exe` (या `.msi`) डाउनलोड करके चलाएँ।
2. अभी कोड-साइनिंग सर्टिफ़िकेट नहीं है, इसलिए Windows अनजान पब्लिशर की चेतावनी दे सकता है। **अधिक जानकारी → फिर भी चलाएँ** चुनें।
3. आगे के वर्ज़न ऊपर से इंस्टॉल होते हैं; आपका डेटा छुआ नहीं जाता।

**macOS (Apple Silicon)**

> **यह एक अनसाइन्ड बिल्ड है।** न Apple Developer ID सर्टिफ़िकेट है, न
> नोटराइज़ेशन, इसलिए macOS इसे तब तक खोलने से मना करेगा जब तक आप ख़ुद
> क्वारंटीन फ़्लैग न हटा दें। नीचे के क़दम जानबूझकर दिया गया वर्कअराउंड है,
> कोई फ़िक्स नहीं — देखें [#2](https://github.com/lingcang728/ZeppBridge/issues/2)।

1. `ZeppBridge_<वर्ज़न>_aarch64.dmg` डाउनलोड करें और `ZeppBridge.app` को Applications में ड्रैग करें।
2. पहला लॉन्च असफल होगा। कौन सा मैसेज आए, यह आपके macOS वर्ज़न पर निर्भर है:
   - **"अज्ञात डेवलपर"** → **ऐप पर राइट-क्लिक → Open → Open।**
   - **"ZeppBridge क्षतिग्रस्त है और नहीं खुल सकता"** → राइट-क्लिक *काम*
     नहीं करेगा। Terminal में यह चलाएँ, फिर ऐप सामान्य रूप से खोलें:

     ```bash
     xattr -dr com.apple.quarantine /Applications/ZeppBridge.app
     ```

   ऐप असल में क्षतिग्रस्त नहीं है। नोटराइज़ न हुआ कोई भी डाउनलोड किया बंडल
   हो, Gatekeeper यही कहता है। ऐसा कमांड सिर्फ़ उस सॉफ़्टवेयर के लिए चलाएँ
   जिस पर आपने भरोसा करने का फ़ैसला किया है — इस प्रोजेक्ट की हर लाइन आप
   GitHub पर पढ़ सकते हैं और ख़ुद बिल्ड कर सकते हैं।
3. macOS बिल्ड CI से गुज़रती हैं (कंपाइल, clippy, टेस्ट) और एक कंट्रिब्यूटर का
   Apple Silicon पर स्मोक टेस्ट हुआ है। मेंटेनर के पास Mac नहीं है और वह सिंक
   या कीचेन बिहेवियर स्वतंत्र रूप से वेरीफ़ाई नहीं कर सकता। अगर यह आपके लिए
   मायने रखता है, तो Windows चुनें।

फ़िलहाल ऐसा क्यों है: नोटराइज़ेशन के लिए Mac चाहिए ही नहीं — CI पहले से
macOS रनर पर चलती है और वहीं साइन और नोटराइज़ कर सकती है। कमी सिर्फ़
Apple Developer Program मेंबरशिप (99 USD/साल) की है, जो प्रोजेक्ट ने नहीं
ली है। अगर वह बदलता है, तो यह सेक्शन हट जाएगा।

**Linux (x86_64)**

> **बिल्ड तो होती है, पर अभी किसी ने चलाया नहीं है।** CI हर push पर कंपाइल
> करती है, टेस्ट चलाती है और पैकेज बनाती है। जो *नहीं* हुआ, वह है एक असली
> Linux डेस्कटॉप पर पूरा साइन-इन-और-सिंक चक्र — इसमें यह भी शामिल है कि टोकन
> आपके कीरिंग में सही से उतरता है या नहीं। इसे रिलीज़ नहीं, एक ऐसी बिल्ड समझें
> जिसे आप टेस्ट करने में मदद कर रहे हैं।

रिलीज़ पेज पर Flatpak, `.deb`, `.rpm` और एक AppImage पब्लिश होते हैं।
कुछ भी साइन नहीं है; डाउनलोड `SHA256SUMS.txt` से मिलाएँ।

```bash
sudo apt install ./ZeppBridge_<वर्ज़न>_amd64.deb      # Debian, Ubuntu
sudo dnf install ./ZeppBridge_<वर्ज़न>_x86_64.rpm     # Fedora, RHEL
flatpak install ./ZeppBridge_<वर्ज़न>_x86_64.flatpak  # कोई भी डिस्ट्रो
```

[Linux गाइड](docs/guides/linux.md) में लिखा है कि डेटा कहाँ जाता है, कीरिंग
न होने पर टोकन कैसे स्टोर होता है, और सोर्स से बिल्ड कैसे करें।

साथ ही एक [हेडलेस कंटेनर इमेज](docs/guides/docker.md) भी है जिसमें सिर्फ़
CLI और MCP सर्वर हैं — NAS या सर्वर पर लाइब्रेरी सिंक रखने के लिए। वह
साइन इन नहीं कर सकती — वह क़दम अब भी एक बार डेस्कटॉप ऐप से ही होता है।

**सपोर्टेड नहीं**: Intel Mac, मोबाइल।

### किस प्लैटफ़ॉर्म पर क्या वेरीफ़ाई हुआ

तीनों पर एक ही ऐप, एक ही इंटरफ़ेस, एक ही फ़ीचर्स — फ़र्क़ सिर्फ़ इतना है कि
इसमें से कितना किसी ने असल में जाँचा है। यहाँ पूछना अंदाज़ा लगाने से बेहतर है।

| | Windows 10/11 (x64) | macOS Apple Silicon | Linux x86_64 |
| --- | --- | --- | --- |
| इंटरफ़ेस और फ़ीचर्स | एक जैसे | एक जैसे | एक जैसे |
| CI में बिल्ड | हाँ | हाँ | हाँ |
| CI में ऑटोमेटेड टेस्ट | हाँ | हाँ | हाँ |
| इंस्टॉलर बिना वर्कअराउंड खुलता है | हाँ (अनजान-पब्लिशर चेतावनी) | **नहीं** — ऊपर अनसाइन्ड बिल्ड का नोट देखें | हाँ |
| साइन-इन, सिंक, एक्सपोर्ट | हर रिलीज़ पर मेंटेनर ने वेरीफ़ाई किया | सिर्फ़ कंट्रिब्यूटर का स्मोक टेस्ट | **अभी कोई नहीं** |
| क्रेडेंशियल स्टोर | Credential Manager, वेरीफ़ाइड | Keychain, स्वतंत्र रूप से वेरीफ़ाई नहीं | Secret Service, **अभी कोई नहीं** |
| ऑटो-अपडेट | वेरीफ़ाइड | बिल्ड हुआ, स्वतंत्र रूप से वेरीफ़ाई नहीं | लागू नहीं — आपका पैकेज मैनेजर |

मेंटेनर Windows पर डेवलप करता है, उसके पास Mac नहीं है और वह डेस्कटॉप पर
Linux नहीं चलाता। ऊपर का कुछ भी यह नहीं कहता कि macOS या Linux टूटे हैं —
यह बताता है कि किसने क्या जाँचा। अगर आप दोनों में से कोई प्लैटफ़ॉर्म चलाते हैं
और कुछ ठीक न लगे, तो एक रिपोर्ट सच में उपयोगी होगी।

**1.0.0 से लोकल डेटाबेस का स्कीमा और अपग्रेड पथ लंबे समय तक निभाए जाने वाली चीज़ माने जाते हैं**: हर माइग्रेशन पहले एक ऑटोमैटिक बैकअप लेती है, और स्नैपशॉट वेरीफ़ाई और रीस्टोर किए जा सकते हैं। आपका डेटा लोकल रहता है — लेकिन स्नैपशॉट उसी डिस्क पर रहते हैं जिस पर डेटाबेस है, इसलिए **अगर ड्राइव ख़राब होने की चिंता है, तो एक कॉपी ख़ुद कहीं और रखें।**

## पहला कनेक्शन

1. ZeppBridge खोलें और साइडबार में **सेटिंग्स** पर जाएँ।
2. कनेक्ट पर क्लिक करें। **ऑफ़िशियल Zepp लॉगिन पेज** अपनी अलग विंडो में खुलता है; अपने सामान्य क्रेडेंशियल से साइन इन करें।
3. "कनेक्टेड" दिखते ही विंडो बंद हो जाती है और ऐप पहला सिंक चलाता है। करीब 40 सेकंड दें।

मुख्यभूमि-चीन और इंटरनैशनल दोनों तरह के अकाउंट चलते हैं; ऐप ख़ुद पहचान लेता है कि आप किस रीजनल सर्वर से हैं।

पहला सिंक 30 दिन लाता है ताकि स्क्रीन पर जल्दी कुछ दिखे, फिर बैकग्राउंड में 180 दिन पूरे होने तक चलता रहता है। प्रोग्रेस दिखती है और आप कभी भी रोक सकते हैं। बाद के सिंक इंक्रीमेंटल होते हैं।

ऐप का हर "पिछले N दिन" सिलेक्टर — ट्रेनिंग और बॉडी स्क्रीन पर, और एक्सपोर्ट पेज पर — आपकी **लोकल** लाइब्रेरी पढ़ता है, क्लाउड नहीं। अगर आप ऐसी सीमा चुनते हैं जो इस मशीन के पास मौजूद डेटा से आगे पीछे जाती है, तो ऐप बता देता है और बाकी लाने का विकल्प देता है। चार्ट में ख़ाली हिस्सा का मतलब *अभी नहीं लाया गया* है, कभी *उस दौरान आपने कुछ रिकॉर्ड नहीं किया* नहीं।

180 दिन से पुराने इतिहास के लिए सेटिंग्स में **दीर्घकालिक आर्काइव और पूरा इतिहास** इस्तेमाल करें: 1/2/3 साल या कस्टम शुरुआत चुनें, और वह महीने-दर-महीने लाता है। किसी भी बिंदु पर रोककर बाद में जारी रख सकते हैं। शुरू करने से पहले वह डिस्क-उपयोग का अनुमान आपके अपने डेटा की असली जमा-दर से लगाता है — किसी हार्ड-कोडेड स्थिरांक से नहीं।

अगर सीमा आपकी लोकल रिटेंशन विंडो से बड़ी है, तो ऐप पहले दीर्घकालिक आर्काइव चालू करवाता है; वरना अभी-अभी लाया इतिहास अगले सफल सिंक के बाद साफ़ हो जाएगा।

लॉगिन पर अटके? ट्रबलशूटिंग और दो बैकअप तरीकों के लिए [कनेक्शन गाइड](docs/guides/connection.md) देखें।

## आपको क्या मिलता है

**ट्रेंड्स**

| पेज | क्या दिखाता है |
| --- | --- |
| **ओवरव्यू** | पिछले कुछ घंटों का हार्ट रेट, आज के कदम, कल रात की नींद का स्ट्रक्चर, यह हफ़्ता आपके अपने पिछले 28 दिनों के मुक़ाबले, और बॉडी व ट्रेनिंग स्टेटस के एंट्री पॉइंट। हर कार्ड खुलता है |
| **हार्ट रेट** | पूरी 24-घंटे की कर्व, साथ में रेस्टिंग हार्ट रेट और दो परिभाषाओं वाले HRV के दिन-दर-दिन ट्रेंड |
| **दैनिक एक्टिविटी** | कदम, दूरी, ऐक्टिव कैलोरी और ऐक्टिव मिनट के दिन-दर-दिन ट्रेंड |
| **बॉडी स्टेटस** | समय के साथ रिकवरी, स्ट्रेस, SpO₂, HRV, श्वास दर और रेस्टिंग हार्ट रेट |
| **ट्रेनिंग स्टेटस** | VO₂max, ट्रेनिंग लोड, लैक्टेट थ्रेशोल्ड, PAI, और हाल का वॉल्यूम ज़्यादा है या कम |
| **हाल के रिकॉर्ड** | हर नींद-सेशन और हर वर्कआउट, सब डिटेल में खुलते हैं |
| **वर्कआउट डिटेल** | दूरी, पेस, हार्ट रेट, प्रति-किलोमीटर स्प्लिट, GPS ट्रैक; रनिंग में पावर और फ़ॉर्म भी |
| **डिवाइस** | हर डिवाइस का मॉडल कहाँ से आया (कैटलॉग मैच या आपकी असाइनमेंट), फ़र्मवेयर, ताज़ा डेटा — कभी भी फिर से असाइन करें |
| **डेटा हेल्थ** (सेटिंग्स → उन्नत और रखरखाव) | हर स्ट्रीम की फ़ेच / पार्स / राइट स्थिति — ख़ाली जगह का मतलब "सिंक नहीं हुआ" है या "कभी मापा ही नहीं गया" |

जिस मेट्रिक में डेटा नहीं, वह "—" दिखाते हुए नहीं बैठती; वह बस दिखती ही
नहीं। और कर्व वहीं टूटती है जहाँ 15 मिनट से ज़्यादा बिना सैम्पल बीत गया,
दोनों सिरों के बीच सीधी लकीर खींचने के बजाय।

**वर्कआउट-बाद इनसाइट और वीकली रिपोर्ट**

किसी वर्कआउट के बाद ऐप उसकी तुलना आपके अपने इतिहास से करता है: उसी दूरी-बैंड की हाल की रन, और पेस, हार्ट रेट व ट्रेनिंग लोड कितने अलग हैं — साथ में यह कि कितने सैम्पल पर टिका है और कॉन्फ़िडेंस क्या है। **आधार-रेखा आप हैं, कोई आबादी-नॉर्म नहीं।** सैम्पल कम हों तो वह यही कह देता है, एक लाइन निकालने के लिए बेंचमार्क नहीं गिराता। ये तथ्य और सबूत हैं; व्याख्या AI पर छोड़ी है।

**AI को सौंपें**

कई प्रॉम्प्ट टेम्पलेट बिल्ट-इन हैं (परफ़ॉर्मेंस सारांश, ट्रेनिंग इनसाइट, रिकवरी असेसमेंट, नींद विश्लेषण)। टेम्पलेट और सीमा चुनें, और ऐप डेटा पैक करता है, डिवाइस पहचान और सटीक लोकेशन हटाता है, क्लिपबोर्ड पर कॉपी करता है और आपके चुने AI साइट को खोलता है।

किसी वर्कआउट के डिटेल पेज का अपना "AI को सौंपें" बटन है, जिसका दायरा
**सिर्फ़ वह एक वर्कआउट** है: ख़ुद वर्कआउट और उसके चलते रिकॉर्ड हुए
पॉइंट-दर-पॉइंट मेट्रिक्स। नींद और कदम जैसे दैनिक रिकॉर्ड साथ नहीं जाते।

2 MB से बड़े पैकेज आपके डेस्कटॉप पर एक फ़ाइल में लिखे जाते हैं, बातचीत में
ड्रैग करने के लिए तैयार।

**फ़ाइल एक्सपोर्ट**

- **JSON** — पूरा स्ट्रक्चर्ड डेटा, स्क्रिप्ट या मॉडल के लिए
- **CSV** — स्प्रेडशीट के लिए टेबलर सारांश
- **GPX** — Strava, Garmin आदि के लिए स्टैंडर्ड ट्रैक

एक्सपोर्ट में क्या होता है: वर्कआउट सारांश (टाइप, शुरुआत और अंत, दूरी,
कैलोरी, औसत और अधिकतम हार्ट रेट, ट्रेनिंग लोड), दैनिक मेट्रिक्स (कदम,
रेस्टिंग हार्ट रेट, HRV, SpO2, स्ट्रेस, श्वास दर, PAI, VO2max) और अपने
स्टेज-टाइमलाइन वाले नींद-सेशन। **सारांश** के बजाय **पूरा** चुनने पर
सेकंड-दर-सेकंड वर्कआउट सीरीज़ और अलग-अलग हार्ट रेट रीडिंग भी जुड़ती हैं।

`.fit` अपना अलग एक्सपोर्ट फ़ॉर्मैट है — एक वर्कआउट एक फ़ाइल, आपके चुने
फ़ोल्डर में लिखी जाती है। इसमें वे सेकंड-दर-सेकंड सीरीज़ हैं जो ZeppBridge
ने Zepp के वर्कआउट डिटेल से डिकोड किए: GPS ट्रैक, हार्ट रेट, स्पीड, ऊँचाई,
रनिंग पावर, ग्राउंड कॉन्टैक्ट टाइम और वर्टिकल ऑसिलेशन, साथ में
प्रति-किलोमीटर लैप और पॉज़ इवेंट। जो फ़ील्ड कभी मापे ही नहीं गए वे बस
अनुपस्थित रहते हैं — फ़ाइल पूरी दिखे इसके लिए कुछ नहीं भरा जाता। कैडेंस
जानबूझकर छोड़ी गई है: उसकी यूनिट हमारे पास मौजूद किसी भी सारांश-फ़ील्ड से
मेल नहीं खाती, और ग़लत यूनिट चुपचाप दोगुना पढ़ देती।

एक्सपोर्ट में क्या नहीं होता: `.tcx`, अकाउंट डिटेल, टोकन या डिवाइस सीरियल
नंबर। GPS ट्रैक GPX और FIT में आते हैं, और सिर्फ़ उन वर्कआउट के लिए जिनमें
ट्रैक असल में होता है।

**समय के साथ भारी नहीं होता**

क्लाउड के रॉ पेलोड लोकल डेटाबेस की सबसे बड़ी चीज़ हैं। ZeppBridge उन्हें
कम्प्रेस करके रखता है — नया सिंक हुआ कुछ भी कम्प्रेस होकर आता है, और अपडेट के
बाद पहला लॉन्च बैकग्राउंड में पुराने पेलोड कम्प्रेस करके डिस्क-जगह वापस
निकालता है, विंडो के ऊपर प्रोग्रेस दिखती है जो ख़त्म होते ही गायब हो जाती है।

किसी पेलोड को बदलने से पहले उसे फिर डीकम्प्रेस करके बाइट-दर-बाइट मिलाया
जाता है, और जो न मिले उसे छोड़ दिया जाता है: रॉ पेलोड ही लोकल में दोबारा
पार्स करने का एकमात्र आधार है, इसलिए कम्प्रेस न करना हमेशा ग़लत कम्प्रेस करने
से बेहतर है। मापा गया 211 MB का डेटाबेस 55 MB निकला।

**चलता छोड़ दें**

विंडो बंद करने पर ऐप ट्रे में रहता है और अपने आप सिंक करता रहता है। अगर आप
नहीं चाहते कि वह चले, तो ट्रे आइकन पर राइट-क्लिक करके बंद करें।

**बिना विंडो के**

हर रिलीज़ के साथ `zeppbridge-tools-<वर्ज़न>-<प्लैटफ़ॉर्म>.zip` भी आता है, जिसमें दो प्रोग्राम हैं:

- `zeppbridge-cli` — नॉन-इंटरैक्टिव: `status`, `sync`, `export`। एग्ज़िट कोड एक स्थिर कॉन्ट्रैक्ट हैं, इसलिए Task Scheduler या cron में साफ़ शेड्यूल होता है।
- `zeppbridge-mcp` — stdio पर सिर्फ़-रीड MCP सर्वर। न पोर्ट, न नेटवर्क। किसी मॉडल को आपका लोकल डेटा पूछने देता है बिना डेटा के मशीन छोड़े।

उपयोग और कॉन्फ़िगरेशन उदाहरणों के लिए [CLI और MCP](docs/reference/cli-and-mcp.md)
देखें। सेटिंग्स का MCP सेक्शन एक टेक्स्ट ब्लॉक भी देता है जिसे आप सीधे किसी
AI को पेस्ट कर सकते हैं, ताकि वह आपकी मशीन के लिए कॉन्फ़िगर करने में मदद करे।

**लोकल सिर्फ़-रीड REST**

सेटिंग्स से आपके अपने स्क्रिप्ट के लिए सिर्फ़ `127.0.0.1` से बँधा एक सिर्फ़-रीड एंडपॉइंट चालू हो सकता है। डिफ़ॉल्ट रूप से बंद है, चालू करने पर टोकन माँगता है, कोई क्रेडेंशियल नहीं लौटाता, और कभी लोकल नेटवर्क पर लिसन नहीं करता।

हर वर्ज़न के बदलाव [CHANGELOG.md](CHANGELOG.md) में हैं। जब सेटिंग्स →
सॉफ़्टवेयर अपडेट → अपडेट जाँचें कोई नया वर्ज़न पाता है, तो वह रिलीज़ नोट भी
सीधे दिखाता है और डाउनलोड के दौरान प्रोग्रेस बताता है।

## अक्सर पूछे जाने वाले सवाल

**क्या मेरा कंप्यूटर चालू रहना चाहिए?**
नहीं। हर लॉन्च आपके न रहने की अवधि पूरी कर लेता है।

**क्या मैं फ़ोन का Zepp ऐप छोड़ सकता/सकती हूँ?**
नहीं। चेन यह है: घड़ी → फ़ोन का Zepp ऐप → Zepp क्लाउड → ZeppBridge। अपलोड के लिए घड़ी को अब भी फ़ोन ऐप चाहिए। उसे कभी-कभी खोलते रहें।

**क्या इससे मेरा अकाउंट बैन हो सकता है?**
ZeppBridge आपके अपने क्रेडेंशियल इस्तेमाल करता है और **सिर्फ़ रीड रिक्वेस्ट भेजता है** — पूरे प्रोजेक्ट में एक भी राइट रिक्वेस्ट नहीं है; grep करके देख सकते हैं। बिहेवियर में यह ऑफ़िशियल ऐप खोलकर अपना डेटा देखने जैसा ही है। फिर भी यह अनौपचारिक इस्तेमाल है, और हम Zepp की ओर से कोई गारंटी नहीं दे सकते।

**कोई मेट्रिक ख़ाली लौटा।**
पहले देखें कि आपकी घड़ी ने उसे सच में मापा था या नहीं। कुछ मेट्रिक्स (लैक्टेट थ्रेशोल्ड, VO₂max) सिर्फ़ ख़ास वर्कआउट के बाद अपडेट होते हैं, साल में मुट्ठी भर बार। सेटिंग्स पेज आपके अकाउंट के लिए हर एक की स्थिति बताता है — ध्यान दें कि **"नहीं मिला" और "आपकी घड़ी सपोर्ट नहीं करती" एक बात नहीं है**: Zepp का API उस डेटा के लिए भी ख़ाली जवाब देता है जो है ही नहीं *और* उन स्ट्रीम नामों के लिए भी जो कभी मान्य थे ही नहीं, इसलिए ख़ालीपन अकेला कुछ साबित नहीं करता।

**मेरा डेटा कहाँ है?**
- **Windows**: इंस्टॉल डायरेक्टरी के बगल में एक `data` फ़ोल्डर (`%APPDATA%` में नहीं)। सेटिंग्स → उन्नत में इसे खोलने का बटन है।
- **macOS**: `~/Library/Application Support/com.zeppbridge.ZeppBridge/data`
- **Linux**: `~/.local/share/zeppbridge/data` (Flatpak:
  `~/.var/app/com.zeppbridge.app/data/zeppbridge/data`)। AppImage या खुला
  tarball `data/` को एक्ज़ीक्यूटेबल के बगल में रखता है — देखें
  [Linux गाइड](docs/guides/linux.md)।

**ऐप स्टार्ट ही नहीं होता — विंडो कभी नहीं आती।**
इसी क्रम में दो चीज़ें देखें:

1. **एरर डायलॉग।** v2.1.2 से स्टार्ट-अप फ़ेलियर एक डायलॉग दिखाता है जिसमें
   सही-सही फ़ोल्डर और OS एरर लिखा होता है, चुपचाप बंद होने के बजाय। पुराने
   वर्ज़न बिना कुछ कहे बंद हो जाते थे, जो ऐसा लगता था कि "ट्रे आइकन है पर
   Open दबाने से कुछ नहीं होता" — वह आइकन पहले से मर चुके प्रोसेस का
   अवशेष था।
2. **लॉग।** डेटा फ़ोल्डर के अंदर `logs/zeppbridge.log` (पिछला सवाल देखें),
   और अगर पिछला लॉन्च विंडो बनने से पहले ही गिरा था तो `logs/startup-error.log`
   भी। बग रिपोर्ट में इन्हें जोड़ें; इनमें पाथ और वर्ज़न नंबर हैं, अकाउंट
   डेटा नहीं।

Windows पर सबसे आम वजह ऐसा डेटा फ़ोल्डर है जिसमें ऐप लिख नहीं पाता —
`.msi`, `Program Files` में इंस्टॉल होता है, जहाँ साधारण यूज़र के पास राइट
एक्सेस नहीं होता। v2.1.2 से ऐप ऐसे में
`%APPDATA%\zeppbridge\ZeppBridge\data` पर शिफ़्ट हो जाता है (जब तक ब्लॉक
हुए फ़ोल्डर में पहले से डेटाबेस न बैठा हो; उस स्थिति में वह ख़ाली चालू होने
के बजाय साफ़ बता देता है)। `ZEPPBRIDGE_DATA_DIR` एनवायरनमेंट वेरिएबल से आप
इसे कहीं भी भेज सकते हैं।

**अनइंस्टॉल के बाद भी मेरा डेटा रहता है?**
हाँ। अनइंस्टॉल `data` फ़ोल्डर, बैकअप, कवरेज लेजर और सेटिंग्स को नहीं छूता। हटाना हो तो हाथ से डिलीट करें।

**क्या डेटाबेस का बैकअप और रीस्टोर हो सकता है?**
हो सकता है। सेटिंग्स कभी भी पूरे डेटाबेस का स्नैपशॉट बना सकती हैं, हर एक के साथ SHA-256 और इंटीग्रिटी जाँच। रीस्टोर कतार में जाते हैं और अगले लॉन्च पर लागू होते हैं — फ़ाइल को परमाणु रूप से बदलने का यही एकमात्र मौक़ा है — और कतार क़दम पहले रिकॉर्ड-गिनती का diff दिखाता है। देखें [बैकअप और रीस्टोर](docs/guides/backup-and-restore.md)।

**मेरे पास एक से ज़्यादा घड़ियाँ हैं — क्या डेटा मिल जाएगा?**
नहीं। हर रिकॉर्ड के साथ लिखा है कि वह किस डिवाइस से आया, और इंटरफ़ेस उन्हें
अलग-अलग रखता है।

**क्या कुछ आपके सर्वर पर भेजा जाता है?**
हेल्थ डेटा, वर्कआउट डिटेल और क्रेडेंशियल कभी आपकी मशीन नहीं छोड़ते। सिर्फ़ तब, जब आप स्पष्ट रूप से "एरर रिपोर्ट भेजें" की पुष्टि करते हैं, ऐप भेजता है: ऐप/पार्सर वर्ज़न, OS, अनपहचाने प्रोडक्ट के सुरक्षित मॉडल-संकेत और फ़ील्ड-स्ट्रक्चर, फ़र्मवेयर वर्ज़न, गिनती समेत अनजान वर्कआउट कोड, और आख़िरी उस रिक्वेस्ट का संख्यात्मक एरर कोड जिसे Zepp क्लाउड ने ठुकराया था (नंबर, कौन सी डेटा स्ट्रीम, और कब — क्लाउड ने जो टेक्स्ट लौटाया वह कभी नहीं)। यह कभी अकाउंट, टोकन, सीरियल नंबर, डिवाइस ID, GPS, हेल्थ वैल्यू, रॉ रिस्पॉन्स या लोकल पाथ नहीं भेजता। कोई ऑटोमैटिक टेलीमेट्री या बैकग्राउंड क्रैश रिपोर्टिंग नहीं है।

## निजता

- **क्रेडेंशियल** डिफ़ॉल्ट रूप से OS के क्रेडेंशियल स्टोर में रहते हैं (Windows Credential Manager / macOS Keychain / Linux Secret Service)। अगर आपका macOS कीचेन अनलॉक नहीं हो पाता, तो आप स्पष्ट रूप से एक निजी सादा-टेक्स्ट फ़ाइल चुन सकते हैं; देखें [macOS क्रेडेंशियल स्टोरेज गाइड](docs/guides/macos-credentials.md)। Linux फ़ाइल और एनवायरनमेंट स्टोर भी सपोर्ट करता है; देखें [Linux गाइड](docs/guides/linux.md)। फ़ाइल स्टोरेज सिस्टम स्टोर से कम सुरक्षा देता है और सिर्फ़ इसलिए कभी चालू नहीं होता कि सिस्टम स्टोर फ़ेल हो गया।
- **हेल्थ डेटा** आपके कंप्यूटर पर एक बिना-एन्क्रिप्टेड डेटाबेस फ़ाइल है। मशीन साझा हो तो अलग OS अकाउंट इस्तेमाल करें।
- **AI पैकेज पहले संशोधित होते हैं**: डिवाइस पहचान, MAC पते और सटीक GPS हटाए जाते हैं, और फ़ाइल लिखती है कि क्या निकाला गया। सटीक ट्रैक सिर्फ़ तब शामिल होते हैं जब आप ऑप्ट-इन करें।
- **मैप लोकल रेंडर होते हैं।** किसी थर्ड-पार्टी मैप सर्विस को कोई रिक्वेस्ट नहीं जाती।
- **एरर रिपोर्ट के लिए स्पष्ट पुष्टि ज़रूरी है**, वे तय allow-list इस्तेमाल करती हैं, लोकल बनती हैं, GitHub अकाउंट नहीं चाहिए, और कभी अपने आप issue नहीं बनतीं।
- सिंक Zepp के सर्वर से संपर्क करता है, इसलिए यह पूरी तरह ऑफ़लाइन ऐप नहीं है।

देखें [सुरक्षा और निजता](docs/reference/security-and-privacy.md)। सुरक्षा समस्याएँ GitHub के निजी वल्नरेबिलिटी रिपोर्टिंग से बताएँ, सार्वजनिक issue से नहीं।

## डेवलपर्स के लिए

Tauri 2 + Vue 3 + Rust। कोर `zeppbridge-core` क्रेट में रहता है; डेस्कटॉप ऐप, CLI, MCP सर्वर और लोकल REST एंडपॉइंट सब उसके ऊपर पतले ऐडाप्टर हैं — SQL, यूनिट कन्वर्ज़न और मिसिंग-वैल्यू नियम कभी दोहराए नहीं जाते।

```bash
npm ci
npm run tauri dev
```

- [डेवलपमेंट](docs/development/development.md) — बिल्ड गेट, कमांड कॉन्ट्रैक्ट, लोकल REST API, स्वीकृति क्रम
- [आर्किटेक्चर](docs/reference/architecture.md) — प्रोडक्ट सीमाएँ, Zepp API मैपिंग, वेरीफ़ाइड बनाम अनवेरीफ़ाइड सूची
- [CLI और MCP](docs/reference/cli-and-mcp.md) — एग्ज़िट-कोड कॉन्ट्रैक्ट, सिर्फ़-रीड टूल, शेड्यूलिंग उदाहरण
- [बैकअप और रीस्टोर](docs/guides/backup-and-restore.md) — स्नैपशॉट, रीस्टोर फ़्लो, कवरेज लेजर
- [Linux](docs/guides/linux.md) — Flatpak, deb/rpm/AppImage, डेटा लोकेशन, क्रेडेंशियल स्टोर
- [macOS क्रेडेंशियल स्टोरेज](docs/guides/macos-credentials.md) — लॉगिन कीचेन उपलब्ध न हो तो फ़ाइल स्टोरेज इस्तेमाल करें
- [Docker](docs/guides/docker.md) — हेडलेस CLI/MCP इमेज, शेड्यूलिंग, रिप्रोड्यूसिबल बिल्ड
- [UI गाइडलाइन्स](docs/development/ui-guidelines.md) — डिज़ाइन टोकन, पेज स्ट्रक्चर, कॉम्पोनेंट

Issue और PR का स्वागत है। कुछ बदलने से पहले आर्किटेक्चर दस्तावेज़ की "अनवेरीफ़ाइड" सूची पढ़ें — इस प्रोजेक्ट का यह मानक स्पष्ट है कि क्या स्थापित तथ्य माना जाए।

## आभार

Zepp का API अनदस्तावेज़ है; कोई डेटा स्ट्रीम है भी या नहीं, यह सिर्फ़ उन लोगों से पता चलता है जिन्होंने उसे पहले चलवाया है। API मैपिंग इन पर आधारित है:

- [m4ary/zepp-health-cli](https://github.com/m4ary/zepp-health-cli) — इवेंट सरफ़ेस का विभाजन और फ़ील्ड वैल्यू
- [Thejuampi/icu](https://github.com/Thejuampi/icu) — उन्हीं API का स्वतंत्र पुनरुत्पादन, क्रॉस-वैलिडेशन के लिए उपयोगी
- [H3llK33p3r/zepp-fit-extractor](https://github.com/H3llK33p3r/zepp-fit-extractor) (Apache-2.0) — वर्कआउट डिटेल डिकोडिंग

इनमें से कोई भी बंडल नहीं है; ZeppBridge उनके दर्ज API-तथ्यों पर आधारित है।
