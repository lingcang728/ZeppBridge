# macOS 凭据存储

[English](macos-credentials.md)

ZeppBridge 默认使用 macOS 钥匙串。如果登录钥匙串受管理、已锁定，或者你无法提供它的密码，可以显式选择文件存储。这是 [issue #72](https://github.com/lingcang728/ZeppBridge/issues/72) 的替代方案，无需修改或重置系统钥匙串。

## 改用文件存储

文件里保存的是**明文令牌**。ZeppBridge 创建的 `credentials.json` 权限为 `0600`（只有当前用户能读写），数据目录权限收紧为 `0700`。它的保护弱于钥匙串：以当前用户身份运行的其他进程仍能读取。不要将此文件放进共享目录、Git，或随数据目录副本分享给别人。

1. 将包含此修复的版本安装到 `/Applications`。
2. **彻底退出 ZeppBridge**，包括菜单栏中的后台实例。只关窗口不够：第二次启动只会唤起旧进程，仍沿用旧进程的存储选择。
3. 打开终端，执行：

   ```sh
   ZEPPBRIDGE_CREDENTIAL_STORE=file /Applications/ZeppBridge.app/Contents/MacOS/zeppbridge
   ```

   如果应用装在其他位置，请相应调整路径。首次运行期间保持终端打开。这条命令只为本次进程设置存储方式，不含令牌，也不需要管理员权限。
4. 在设置中连接 Zepp 账号。网页登录、HAR 导入、手动填写均使用选中的文件存储，已有健康记录会保留。如果令牌只存在于锁定的钥匙串中，需要重新登录；ZeppBridge 无法读取或迁移那份无法访问的令牌。
5. 登录保存成功后退出应用。之后可直接从 Finder 或程序坞正常启动：只要同一数据目录中已有 `credentials.json`，应用就会继续使用文件存储，无需再次设置环境变量。

在「设置 → 高级 → 打开数据文件夹」查看实际使用的数据目录。`auth.json` 仍只保存账号和区域等元数据；令牌存在独立的 `credentials.json` 中。如果开启本机 API，它的令牌也存在这个文件中。桌面应用和 CLI 使用同一数据目录时，遵循相同的存储选择规则。

## 选择规则与切回钥匙串

- `ZEPPBRIDGE_CREDENTIAL_STORE=file`：显式选择文件存储。
- `ZEPPBRIDGE_CREDENTIAL_STORE=keychain`：显式选择钥匙串，即使已有凭据文件也一样。`keyring` 是 `keychain` 的别名。
- 未设置或设置为空时：有凭据文件则继续使用文件，否则使用钥匙串。钥匙串访问失败时不会静默将令牌写入文件。
- 不认识的值会报错。Linux 的 `env` 和 `secret-service` 选项不适用于 macOS。

退出账号会删除所选存储里的 Zepp 令牌，保留健康记录。如果文件中还有本机 API 令牌，它会保留；最后一个令牌被删除后，凭据文件也会删除。此后不带显式设置启动时会再次使用钥匙串。如果钥匙串仍不可用，重新连接前请再次用上面的文件存储命令启动。

要永久切回钥匙串，请退出应用，将上面命令中的 `file` 换成 `keychain` 后启动并重新登录。确认保存成功后退出，仅删除实际数据目录中的 `credentials.json`。这会清除旧的文件副本及其中的本机 API 令牌，API 客户端可能需要更换令牌。切换存储不会自动迁移或删除另一种存储里的条目。

## 验证范围

macOS CI 测试覆盖文件权限、保存、在不带环境变量的新进程中恢复、旧版元数据迁移、本机 API 令牌和退出账号。真实受管理 Mac 上仍需验证完整登录与同步；CI 不会复现组织的钥匙串策略或 Touch ID 弹窗。
