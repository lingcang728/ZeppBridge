# 动效基线（2026-11-12 修复计划 A0 / A5）

只放数字和结论，不放截图。测量台在 `scripts/motion/`（`bench.py` 出表，`strip.py` 出给人看的慢放条带，
`harness.py` 是公用的打开应用 + 逐帧采样；设 `ZB_MOTION_GPU=1` 走真显卡 D3D11，默认软件 GL 量不出 GPU 光栅那一下）。规则本身见 [ui-guidelines.zh-CN.md](ui-guidelines.zh-CN.md)
「动效：一个原语，七条规则」。

## 怎么测

- 跑的是 `dist`（`vite build` 之后）+ 演示数据（`?demo=1`），无头 Chrome，**CPU 降速 4×、DPR 2**、1440×900，
  和记忆里「卡顿要降速量」一致；页面形变另跑一遍不降速（1×），原因见下。
- 自动降级（`html[data-effects=lite]`）在测量时被挡掉：降速以后机器分级会判成低档，整套动效被关，量到的是另一套东西。
- 采样是页面里的 `requestAnimationFrame`：每帧读一遍计算样式（透明度连乘到根、`clip-path` 裁出来的可视框）。
  **主线程被堵住的那段它看不见**——合成器上的动画照走，采样却一帧都没有。所以 4× 下页面形变的「去程 / 回程」
  被挂载新页的长任务淹没，掉头的比值以 1× 为准。
- 指标：起步 = 点击到第一帧可见变化；最长停顿帧 = 变化段里相邻两帧完全一样的最长连续数；空板帧 = 窗口已经比卡大
  1.5 倍、里面的卡拷贝和内容都淡于 0.2；截断 = 收起途中还很大的板下一帧就没了；被吞的点击 = 连点时点了没换路由；
  回程 / 去程 = 窗口开始长 → 开始缩 → 落回卡上（或撤掉）两段的时长比。

从人刚才看到的位置走过去，单帧最大位移 88 px（整段 361px 摊在形变里）。

结论：
- 「设置卡收起时被截断」在全效果下复现不出来（截断 0），机理找到了：卡叠的动画以前不在快进豁免里，开合会换路由，
  路由钩子里的 `settleMotion` 只要不落在 320ms 的「别快进」窗口里，就把正在关的卡压进 90ms 放完、紧接着 closingId
  清掉、大卡下场——看上去就是关到一半被截掉。现在卡叠是 `createFlight` 的飞行（不被快进），同一路由里只换参数时
  也不再调 `settleMotion`；中途降成低档特效时，已经开跑的关卡照样放完。
- 连点不再设 320ms 保护：5 次开关一次都不吞，停在最后一次要的状态。
- Esc 关卡 11 → 8、开到一半按 Esc 10 → 1。Esc 关卡剩下那 8 帧在收尾之后（鼠标停在源卡上的悬停过渡），不在形变里；
  开到一半按 Esc 是同一组动画掉头。
- 第一次打开「引导」卡的起步（112 → 183ms）是首次激活卡体的成本，每次跑都在这个范围里浮动，和形变无关。

结论：
- 展开不再先停在起点等帧稳、也不等首屏数据：大页（心率）的起步从约 700ms 降到约 370ms（4×），1× 下几十毫秒；
  空板帧从 5 / 2 降到 0（卡拷贝顶到交接点，内容画好了才接手）。
- 开到一半按返回：在路由守卫里当场掉头（合成器上立刻往回走），Vue 换完页以后按此刻的样子、倒过来的曲线接力，
  回程 / 去程在 1× 下 0.76–1.2（刚点开 15% 就返回时偏快：采样把去程开头那几十毫秒的挂载也算进了去程）。4× 下的比值偏离，是采样被长任务吃掉，不是动画。
- 快速连点五次开 / 返回：停在最后一次要的页上（结束时文档里只有一页、没有残留的形变层）；大页最长停顿从 33 帧降到 1。
- 代价：展开时图表等落地才挂（`lib/motion/budget.ts`），所以刚打开睡眠这类图表多的页、马上又返回时（4× 下 2 秒内），
  返回要等图表那一下长任务做完才开始动。1× 下看不出来。

### 第二轮（2026-11-12 下午，用户录屏否掉了上面「不等帧稳、图表落地才挂」那两条）

上面的做法量出来起步很快，真机上却是：窗口放出来的第一帧已经长了三四成（新页第一次上屏那一两帧被吞），里面只有
缩在角上的卡拷贝和一块空板，内容到 28% 才蹦出来，图表落地以后再淡入一遍——「每次都会重绘，动画也很快，闪来闪去」。
量「起步 ms」量不出这个：它只看第一处变化，不看窗口长大时里面有没有东西。改成：

- 新页照旧轻着挂（图表只放壳），背后的模糊在新页上屏那一帧就开始糊——这是「点下去的反应」。
- 窗口停在卡上：图表一帧一张地挂（都在卡拷贝后面），挂完（上限 260ms）、帧稳（上限 120ms）才起飞。
- 交接提前到时间轴的 4%–24%，先后交替不叠影；曲线换成缓起的 `cubic-bezier(.3, .1, .15, 1)`，时长 540 × PACE。
- 收到一半又点开同一张卡：以前收回那段没记路由（`path: ''`），接力一直没生效，窗口先跳回卡上；现在从此刻的框接着长。

1×（无头 Chrome、DPR 2，心率页 5 张图）点击 → 起飞约 370–480ms，其中新页挂载约 150ms、图表约 150ms，其余是帧稳的上限
（无头 Chrome 的帧间隔 8 / 17ms 交替，永远判不成「稳」，真机上是两三帧）；睡眠页（没有图表）约 290ms。
起飞后窗口里每一帧都是带图表的真页面，落地后没有任何重画。4× 下起飞被新页自己的长任务拖到 1 秒以上——
那种机器本来就走低特效。逐帧条带用 `scripts/motion/strip.py` 看。

## 剩下没做到的

- 4× 下新页挂载本身仍有一段长任务，展开第一下的反馈是「卡拷贝顶在原位」，要等长任务过去窗口才开始长；
  要再快只能让新页挂得更轻（或者拆成多帧挂）。
- 收回途中按 Esc 仍是把剩下的部分在 200ms 内放完（落到卡上），没有改成掉头：收回本来就是「返回」，再按一次 Esc
  的意思是「快点」。

## 收回落地停留段（2026-11-13）

落地停留段（`PAGE_LAND_AT` / `LAND_HOLD`）和 `settleCssAnimations` 上线后重跑 `bench.py`（4×）。`page.small.*`（概览 → /sleep → 返回）
的帧间隔看起来很大：最大帧间隔约 1.2–2 s。同一台机器上用 HEAD 的构建做了 A/B 剖析（CDP Profiler，返回后 3 s），
两边的长任务形状一样：返回后约 1.0 s 和 1.2 s 处各有一段 0.7 s、1.0 s 的长任务。主要耗时是 `(program)`，也就是样式、
布局和光栅，其次是 `getBoundingClientRect` 约 400 ms。这是 4× 降速下的老问题，不是这次的改动引入的，
`getAnimations` 两边都约 150 ms。慢放条带见 ui-guidelines 第 8 条：四个场景落地前后都没有双影，也没有动画从头再放。
